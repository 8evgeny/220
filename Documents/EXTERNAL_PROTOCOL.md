# GOEN-220 — Внешний сетевой протокол

## 1. Общие сведения

| Параметр | Значение |
|----------|----------|
| Транспорт | UDP (основной) + TCP Server (альтернативный) |
| Порт приёма команд | `52516` (настраиваемый, `Network.UDP_Port_HostPC`) |
| Порт отправки телеметрии | `52515` (настраиваемый, `Network.UDP_Port_Edge2`) |
| IP устройства (daemon) | `192.168.1.96` (настраиваемый, `Network.IP_Edge2`) |
| IP хоста (приёмник телеметрии) | `192.168.1.54` (настраиваемый, `Network.IP_HostPC`) |
| Размер команды | **516 байт** (фиксированный) |
| Порядок байт | Little-Endian (x86/ARM нативный) |
| Период телеметрии | 40 мс (25 Гц) |

### 1.1 Режимы работы видеоканала

Устройство поддерживает два режима передачи видео:

1. **MPEG-TS / SRT** (по умолчанию) — видеопоток передаётся через GStreamer в формате MPEG Transport Stream поверх UDP или SRT. Телеметрия встраивается в поток как KLV-метаданные.
2. **Legacy UDP** — кадры передаются фрагментированными UDP-пакетами того же протокола (флаг 0x0300).

## 2. Структура пакетов

Все пакеты начинаются с 4-байтового заголовка:

```
Смещение  Размер   Поле
────────  ──────   ─────────────────────────────────────
0         uint16   pkt_preambule        (всегда 0x0000)
2         uint16   service_pkt_flag      (тип пакета)
```

### Типы пакетов по `service_pkt_flag`:

| Значение | Тип | Направление |
|----------|-----|-------------|
| `0x0100` | Команда / Телеметрия | Host → Device (команды) / Device → Host (телеметрия) |
| `0x0200` | Видео-сервисный (описание кадра) | Device → Host |
| `0x0300` | Видеоданные (фрагмент кадра) | Device → Host |

## 3. Пакет команды (Host → Device)

**Размер: ровно 516 байт.**

```
Смещение  Размер       Поле              Описание
────────  ──────────   ────────────────   ─────────────────────────────────────
0         uint16       pkt_preambule      Всегда 0x0000
2         uint16       service_pkt_flag    Всегда 0x0100
4         uint8        CMD                Всегда 0x00
5         uint8        STATUS             Всегда 0x00
6         uint16       SRC                Источник: 0x0000 (Host)
8         uint16       DST                Назначение (см. §3.1)
10        uint16       WORD_COUNT         Размер PAYLOAD в словах (не используется строго)
12        uint16       CODE               Код команды (CMD_CODE, см. §4)
14        uint16       SUPP               Supplemental / поддержка
16        uint8[12]    PAYLOAD            Данные команды (зависят от CODE)
28        uint8[488]   RESERVE            Зарезервировано, заполнять 0x00
```

### 3.1 Маршрутизация по полю DST

| DST | Назначение | Обработка |
|-----|-----------|-----------|
| `0x0103` | Основное устройство (фиксированная плата) | `processCmd()` — основной набор команд (§4) |
| `0x090C` | Плата Gowin Mini640 | Управление кулером ТПВ-С модуля |
| `0x020C` | Гироплатформа (GSP), регистр motor | Специальная команда выключения моторов |
| `0x020A` | Гироплатформа (GSP), регистр zero_pos_x | Установка нового нуля по оси X (см. §3.3) |
| `0x0209` | Гироплатформа (GSP), регистр zero_pos_z | Установка нового нуля по оси Z (см. §3.3) |
| `0x020B` | Гироплатформа (GSP), регистр arretir | Управление арретированием (см. §3.4) |

### 3.2 Обработка пакетов Mini640 (DST = 0x090C)

Поле CODE интерпретируется как:
- `CODE = 0` — кулер OFF
- `CODE = 1` — кулер ON

### 3.3 Установка нового нуля ГСП (VDB write, DST = 0x020A / 0x0209)

Команды записи в регистры VDB-шины ГСП для установки пользовательского смещения нуля.

| DST | Регистр | Действие |
|-----|---------|----------|
| `0x020A` | `en_vdb_gsp_zero_pos_x` | Установить новый ноль по оси X (тангаж) |
| `0x0209` | `en_vdb_gsp_zero_pos_z` | Установить новый ноль по оси Z (рыскание) |

**Формат данных:** первые 4 байта PAYLOAD (смещение 12 в пакете, поле CODE) интерпретируются как `float` (IEEE 754, LE) — угол нового нуля в градусах.

**Поведение:**
1. Значение сохраняется в конфиг (`GyroPlatform.ZeroXOffset` / `GyroPlatform.ZeroZOffset`).
2. При формировании телеметрии из текущих углов ГСП вычитается offset:
   ```
   телеметрия_ANGLE_Y = фактический_угол_X − ZeroXOffset
   телеметрия_ANGLE_Z = фактический_угол_Z − ZeroZOffset
   ```
3. Offset сохраняется между перезапусками.

**Массив двух осей (set_new_angles, `WORD_COUNT = 2`):** по DST = `0x0209` с `WORD_COUNT = 2`
передаются сразу оба нуля — массив из двух `float` [Z, X]:

| Смещение | Поле | Значение |
|----------|------|----------|
| 12 | CODE (+ SUPP, 4 байта) | `float` угол Z → `ZeroZOffset` |
| 16 | PAYLOAD[0..3] | `float` угол X → `ZeroXOffset` |

Оба offset сохраняются одним пакетом (эмулируются два независимых сохранения X и Z).

### 3.4 Управление арретированием ГСП (VDB write, DST = 0x020B)

Поле данных (смещение 12, 4 байта) — `uint32` вида `(axis << 16) | mode`:

| Поле | Значения | Описание |
|------|----------|----------|
| `axis` (ст. 16 бит) | 0 = ALL, 1 = X, 2 = Z | Ось арретирования |
| `mode` (мл. 16 бит) | 0 = OFF, 1 = ON | Снять / установить |

**Текущий статус на сервере:** команда принимается и логируется, дальнейшая
обработка пока не выполняется (зарезервировано под будущую интеграцию приводов).

## 4. Коды команд (основной канал, DST = 0x0103)

### 4.1 Управление видео

| CODE | Название | PAYLOAD описание |
|------|----------|------------------|

| `0x01` | CONTR_ENHANCEMENT | `[uint8 ch_id][uint8 ch_en]` — обработка повышения контраста |
| `0x4A` | PROCESSING_BRIGHTNESS | `[uint8 ch_id][uint8 corr]` — коррекция яркости (-128…+127) |
| `0x4B` | PROCESSING_CONTRAST | `[uint8 ch_id][uint16 corr]` — коррекция контрастности (0…2, 32768=1.0) |
| `0x4C` | NEGATIVE_MW | `[uint8 inv]` — инверсия ТПВ-С: 0=горячее яркое, 1=горячее тёмное |
| `0x40` | SWIR_GAIN_CONTROL | `[uint8 ch_id][uint8 mode]` — усиление ТПВ-Б: 0=низкое, 1=высокое, 2=авто |

## 12. Ограничения и примечания

1. **Размер команды строго 516 байт.** Пакеты другого размера отбрасываются с предупреждением в лог.
2. **Endianness:** Все многобайтовые поля — little-endian (ARM/x86 native).
3. **Структура `TARGET_3`** содержит неочевидное смещение (`HOLE1[11]`) из-за различий выравнивания; необходимо использовать точные байтовые смещения.
4. **Поле `SET_SPEED` (CODE=0x24)** использует нестандартное упаковывание двух int24 в 6 байт: `int32_t Wy:24; int32_t Wz:24`. В C/C++ это зависит от реализации битовых полей. Рекомендуется использовать `SET_SPEED_DEG` (CODE=0xA7) с float-значениями.
5. **Команда TURN_OFF_MOTORS** не имеет CODE в PAYLOAD; распознаётся по сочетанию `CMD=0x00, SRC=0x0000, DST=0x020C` (GSP, регистр motor).
6. **Каналы (ch_id):** 1 = ТВ, 2 = ТПВ-Б (SWIR), 3 = ТПВ-С (LWIR). Значения могут варьироваться в зависимости от конфигурации изделия.
